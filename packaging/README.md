# Registry launchers

`npx causari` and `pipx run causari` reach the same binary as every other
installer. The two packages here are launchers, not builds: each holds a few
kilobytes of code, no binary, and does nothing at install time. On first run
the launcher downloads `causari-v<version>-<target>.tar.gz` (`.zip` on
Windows) from the GitHub release that matches its own version, checks the
archive's SHA-256 against the release's `SHA256SUMS.txt`, unpacks `causari`
and `re` into a per-version cache and runs the requested one with the caller's
arguments. No telemetry, no postinstall network access, no dependencies.

| | `packaging/npm/` | `packaging/pypi/` |
|---|---|---|
| registry name | `causari` | `causari` |
| commands | `causari`, `re` | `causari`, `re` |
| runtime | Node ≥ 18, built-ins only | Python ≥ 3.9, standard library only |
| archive readers | own ustar/pax/GNU tar and zip (stored, deflate) readers; no `tar.exe`, no `Expand-Archive` | `tarfile`, `zipfile` |
| hand-off | `child_process.spawn`, exit code and signals relayed | `os.execv` (child process on Windows) |
| cache | `$XDG_CACHE_HOME` → `%LOCALAPPDATA%` (Windows) → `~/.cache`, then `causari/<version>/<target>/` | same |
| tests | `scripts/tests/test_npm_shim.sh` (real download, cache hit, tampered archive, missing checksum, `CAUSARI_BINARY`, exit code, unsupported platform) | `packaging/pypi/tests/` (fake downloader) |

Environment variables, both launchers: `CAUSARI_VERSION` runs another
release; `CAUSARI_BINARY` names an existing binary and skips the download;
`CAUSARI_DOWNLOAD_BASE` points at a mirror of the release directory.

The zip reader in the npm launcher is built in rather than shelling out to
`tar.exe` or `Expand-Archive`: it does not depend on `PATH` or on the
PowerShell execution policy, and the same code runs, and is tested, on every
platform against the real Windows release archive. It handles the two methods
7-Zip writes for the release (`stored`, `deflate`) and refuses anything else.

## Versions

One version everywhere: `Cargo.toml` is the source and
`scripts/audit_surfaces.py` (`canon/canon.json → version_sources`) fails the
gate when `packaging/npm/package.json` or `packaging/pypi/pyproject.toml`
disagree. A release therefore bumps both files together with `Cargo.toml`,
`server.json`, `site/index.html` and the plugin manifests. The launchers are
published only for a tag whose version they carry;
`.github/workflows/publish-shims.yml` checks that before uploading.

## Publishing

`publish-shims.yml` runs on every release tag (and on a release published by
hand, and by `workflow_dispatch` with a version). It waits until the release
serves `SHA256SUMS.txt`, runs each launcher against that release, and uploads
through Trusted Publishing (OIDC) on both registries. No registry token is
stored in this repository. A version that is already on a registry is
skipped, so running the workflow twice is harmless.

## Owner: one-time setup

Both registries authenticate the workflow by its GitHub identity: owner
`croviatrust`, repository `causari`, workflow file `publish-shims.yml`. The
jobs run in the GitHub environments `npm` and `pypi`; create both under
repository Settings → Environments (a protection rule on them is optional
and adds a manual approval to every publish).

### npm

npm cannot create a package through Trusted Publishing: the package has to
exist before a trusted publisher can be attached to it
([npm/cli#8544](https://github.com/npm/cli/issues/8544)). The first version is
therefore published by hand, once, from a checkout of the release tag.

1. `npm login` as the account that will own the package (2FA enabled).
2. From the tag: `git checkout v0.3.0 && cd packaging/npm && npm publish --access public`
   (no `--provenance` here; provenance is generated by the workflow from the
   next release on).
3. On npmjs.com → Packages → `causari` → Settings → Trusted Publisher →
   GitHub Actions:
   - Organization or user: `croviatrust`
   - Repository: `causari`
   - Workflow filename: `publish-shims.yml` (file name only, with the extension)
   - Environment name: `npm`
   - Allowed actions: `npm publish` (configurations created after
     2026-09-03 default to staged publishing only; tick direct publishing, or
     approve each staged release by hand)
4. Same page → Publishing access → "Require two-factor authentication and
   disallow tokens". Trusted publishers keep working; classic tokens stop.
5. Optional, from the CLI instead of step 3:
   `npm trust github causari --repository croviatrust/causari --file publish-shims.yml --environment npm --allow-publish`

Requirements the workflow already meets: GitHub-hosted runner, `id-token:
write`, npm CLI ≥ 11.5.1 (it installs `npm@latest` on Node 24),
`repository.url` in `package.json` equal to the GitHub repository, and no
`NODE_AUTH_TOKEN` in the publish step. `actions/setup-node` must not set
`registry-url`: that writes `_authToken=${NODE_AUTH_TOKEN}` and, with no
secret, exports the placeholder `XXXXX-XXXXX-XXXXX-XXXXX`. npm then publishes
with that placeholder instead of Trusted Publishing, and the registry
answers 404. Check with `npm view causari` and
`npm audit signatures` after the first workflow publish.

### PyPI

PyPI accepts a *pending* publisher for a project that does not exist yet, so
no upload by hand is needed.

1. On pypi.org, logged in as the account that will own the project:
   Account settings → Publishing → "Add a new pending publisher" → GitHub:
   - PyPI project name: `causari`
   - Owner: `croviatrust`
   - Repository name: `causari`
   - Workflow name: `publish-shims.yml`
   - Environment name: `pypi`
2. The first successful run of `publish-shims.yml` creates the project and
   turns the pending publisher into its trusted publisher. Nothing else to do.
3. Optional: on the project page → Settings → Publishing, confirm that the
   only publisher is the one above.

### After the first publish

Add the install lines to `README.md`, `site/index.html` and `site/llms.txt`
(the commit "install: npm and PyPI lines" holds them), then check both
registries from a clean machine:

```sh
npx causari@latest --version
pipx run causari --version
```
